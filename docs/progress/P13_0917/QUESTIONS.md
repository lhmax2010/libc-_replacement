# 疑问与边界

1. W2(d) 已异步提出：如果第二个异常在第一个异常展开期间逸出析构，C++ 会 terminate；外层 catch 无法改变该规则。将分别实测析构内自行捕获、正常退出时析构抛出、展开时析构第二异常逸出，不能替换概念。待人工确认要求的具体语义。
2. P12 的 GNU-only 对照调用的是 adaptor 后端 POD 函数，不是原始 ewk_parse_cookie 的分配失败约定。W3 会另做真实原始入口对照；不得把它称为原 API 自带负 errno 返回。
3. 当前反向链的后端是 GNU TU，不是 libc++ TU；生产方向缺真实 libc++ EWK。P13 固定两侧 runtime 版本引用，但不把反向实测外推为生产方向已验。
4. 新增构建条件：GNU gold 实测可链接。原平台 linker 的失败记录保留；产品 linker/GN/RPM 尚需验证。未改全局 linker、平台配置或运行库。
5. 同步 catch-all 合同不包括线程取消、强制展开、栈溢出、信号故障、析构双异常及其他 terminate 路径。本轮按任务书不测试取消，不据此声明取消安全。
