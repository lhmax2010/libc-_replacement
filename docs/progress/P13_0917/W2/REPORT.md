# 回归、扩展同步异常与清理计数

结论：已覆盖正常场景未见退化；同步异常映射及清理计数通过。**“展开时第二异常逸出析构也不终止”未满足，外层捕获不能实现该保证**；该项单独等待人工确认契约，不写为全部通过。

| 范围 | 结果 | 索引 |
| --- | --- | --- |
| 12 场景，两种 adaptor 放法 | 每种 5 个进程、每进程 12 场景，四字段/expiry/返回/销毁全部通过 | EWK_RESULTS.json |
| 同侧 GNU 正向、无 adaptor 混库检错对照 | 同侧 12×5 通过；无 adaptor 5/5 SIGSEGV | 同上 |

全部 x86_64 原生，当前真实 provider 是 GNU Chromium；没有模拟 libc++ EWK、没有开发板或取消测试。主矩阵逐进程确认 maps 和具体值，不能由退出码推断正确性。

## 2. 扩展异常

EXCEPTIONS.json 共 80 个新进程：下列每行都是两种放法各 5 次。每次先成功调用真实 provider 并核验 maps，再在**adaptor 后端测试点**注入异常；不是修改 provider。

| 后端条件 | 实测 | 含义 |
| --- | --- | --- |
| reserve(max_size+1) 引发 length_error | false/EOVERFLOW，输出不变 | 真正调用本侧标准库长度检查，不只是伪造返回码 |
| 显式注入 invalid_argument | false/EINVAL，输出不变 | 原解析器会抛此类型是 NOT_OBSERVED；不能说真实解析已走此路径 |
| 自定义非标准类型 | false/EIO，输出不变 | catch-all 的检验 |
| runtime_error | false/EIO，输出不变 | std::exception 分支 |
| 外层 bad_alloc；析构内部抛自定义异常并自行捕获 | false/ENOMEM，nested=1，输出不变 | 有第二次 throw，但未逸出析构 |
| 外层 bad_alloc；第二异常逸出析构 | **5/5 SIGABRT（每种放法）** | 未满足原“确认不终止”要求；不是可由外层 catch 修复的路径 |
| 正常退出时析构抛异常（无既有展开） | false/EIO，输出不变 | 与上一行严格不同 |
| catch 第一个异常后再抛 invalid_argument | false/EINVAL，输出不变 | 异常处理器内替换异常，不是展开中双异常逸出 |

70 个进程正常返回预期错误，10 个进程记录析构双异常的终止边界。两种放法的 SIGABRT 原文及退出码完整保留。没有把“析构内捕获”替代“任何析构第二异常都能由外层兜住”。

## 3. 清理计数

现场 `valgrind` 不可得，使用测试专用 C 分配观察 DSO；不安装、不进入发布 adaptor，也不参与 provider 路由。它通过测试应用的明确链接依赖观察当前线程的 malloc/calloc/realloc/free，内部固定大小表，无动态分配。观测窗口在预热之后、受测调用之前开始，在调用返回后结束。

每个进程先做正向检错对照：保留 37 字节时应检出 live=1/bytes=37，释放配对时应检出 live=0。再测六类可返回的异常 × 三个失败位置（首个字段复制后、全部初始字段复制后、全部输出转换后）× 两放法 × 5 次，共 **180 次**。

所有窗口均观测到非零分配数，allocations=frees、live=0、bytes=0、overflow=0；四字段/存储地址/expiry 不变，恢复调用通过。详见 ALLOCATIONS.json 的值行与 raw/alloc_* 完整记录。分配索引记录 raw SHA，避免在 JSON 中重复存放 maps；原始输出未修改。

这是所测当前线程、malloc 家族、固定输入和失败点的窗口计数，同时包含前端、后端及异常对象的分配；不是任意分配器、后台线程、mmap、进程常驻缓存或完整程序无泄漏证明。析构双异常终止路径不能给出“资源已释放”保证，明确排除。

## 4. 未覆盖与当前判断

POD 空指针/超长被拒绝，不等于能验证悬空借用区或损坏 C++ 对象。未测并发、取消、栈溢出、信号、生产方向真实 libc++ EWK、armv7l、产品安装升级。当前构建采用 W1 的显式版本绑定及 GNU gold 条件；不会把这些检查写成通用跨库 ABI 保证。

W1 的原始分配失败阻断已经修复；W2 中字面要求的“析构双异常逸出不终止”没有实现。W3 将把两者分别写入契约和待决项，而非给出无条件上线结论。
