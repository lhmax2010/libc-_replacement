# 交接结论

**当前状态：PARTIAL。** 原普通分配异常的终止已修复。经人工审阅，以下三项分别归为行为变化、provider 外部缺陷和语言固有限制，不再作为 adaptor 缺陷阻断；这不等于生产部署验收完成。最新核查见 [后续结论](../P14_0917/FINAL.md)。

| 必答问题 | 结果 |
| --- | --- |
| 原 5/5 SIGABRT 是否变成存活？ | 是。固定 TU 运行时版本绑定并补齐同步捕获后，原用例与 GNU-only 对照各 5/5 返回 -ENOMEM、存活；两放法共 120 次错误位置/真实大输入测试保持输出。不是对任意异常的封闭证明。 |
| 已过场景是否被破坏？ | 12 场景、17 边界、前端故障、POD 协议和 vector 数据层回归未见退化；无测试宏的发布候选两放法也通过 12×5。 |
| 错误契约是什么，与原接口一致吗？ | 公开 bool 不改；同步 bad_alloc→false/ENOMEM，length_error→EOVERFLOW，invalid_argument→EINVAL，其他→EIO；映射失败时输出不变。原始 GNU EWK 可将 bad_alloc 抛给应用，因此异常传播不完全一致。完整资源释放保证尚未成立。 |
| 还剩什么？ | 生产方向、armv7l、并发/取消/栈溢出、真实回调、产品 linker/GN/RPM；provider 候选补丁尚缺产品构建与修后验证。 |

W2 的 180 次窗口计数通过只覆盖指定注入点；W3 进一步在真实 malloc 点失败发现稳定累计的未配对分配，原始 GNU 入口也有。两类实验都保留，不能互相覆盖。细节见 [错误契约](W3/ERROR_CONTRACT.md) 与 [部署更新](W3/DEPLOYMENT_UPDATE.md)。

## 三项重新归类

- **异常传播：行为变化，已记录。** 原始 GNU API 可向应用抛 bad_alloc；adaptor 转为 false/ENOMEM，是人工要求的同步错误契约。`extern "C"` 并不自动禁止 C++ 异常；这里是显式设计选择，不宣称语言强制如此。
- **provider 泄漏：外部缺陷，已定位并提交候选草案。** GNU 原始入口每次遗留的 3 块、834 字节已对应到 ParsedCookie 的 vector 存储及名称/值。候选通过补丁应用检查，但因缺产品生成头/构建闭包，**修后归零及正常路径验证仍为 NOT_OBSERVED**，不能写“patch 已验证”。见 [定位与候选](../P14_0917/W2/REPORT.md)。
- **展开中的双异常：语言固有限制。** GNU-only 同一夹具 5/5 SIGABRT，与既测双运行时 adaptor 路径一致。另三格 GNU-only 均存活；“正常退出析构抛出”使用显式 noexcept(false)，不能改写成 GNU 会终止。见 [四格对照](../P14_0917/W1/REPORT.md)。

平台源码和配置未改。实验原始记录保留；状态变更是依人工裁决重新归类，不是把未完成验证改成通过。完成本轮交接后停，交人工审阅。
