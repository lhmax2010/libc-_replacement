# 交接结论

**修复了原普通分配异常的终止，但本夜不能将候选改为可上线：发现新的真实 provider 清理缺口。**

| 必答问题 | 结果 |
| --- | --- |
| 原 5/5 SIGABRT 是否变成存活？ | 是。固定 TU 运行时版本绑定并补齐同步捕获后，原用例与 GNU-only 对照各 5/5 返回 -ENOMEM、存活；两放法共 120 次错误位置/真实大输入测试保持输出。不是对任意异常的封闭证明。 |
| 已过场景是否被破坏？ | 12 场景、17 边界、前端故障、POD 协议和 vector 数据层回归未见退化；无测试宏的发布候选两放法也通过 12×5。 |
| 错误契约是什么，与原接口一致吗？ | 公开 bool 不改；同步 bad_alloc→false/ENOMEM，length_error→EOVERFLOW，invalid_argument→EINVAL，其他→EIO；映射失败时输出不变。原始 GNU EWK 可将 bad_alloc 抛给应用，因此异常传播不完全一致。完整资源释放保证尚未成立。 |
| 还剩什么？ | provider 真正分配失败后的未配对分配；析构双异常逸出无法由外层兜住；生产方向、armv7l、并发/取消/栈溢出、真实回调、产品 linker/GN/RPM。 |

W2 的 180 次窗口计数通过只覆盖指定注入点；W3 进一步在真实 malloc 点失败发现稳定累计的未配对分配，原始 GNU 入口也有。两类实验都保留，不能互相覆盖。细节见 [错误契约](W3/ERROR_CONTRACT.md) 与 [部署更新](W3/DEPLOYMENT_UPDATE.md)。

当前实际状态仍是 **RELEASE_BLOCKED，阻断原因已更新**，不是把 P12 的旧 SIGABRT 结论原封不动保留。修正 provider 的异常清理需要另行授权，本轮没有改平台源码或配置。疑问已记 QUESTIONS.md，交人工裁决。
