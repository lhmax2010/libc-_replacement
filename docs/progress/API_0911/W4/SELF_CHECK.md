# 成文与证据自检

## 人工式逐项核读

| 检查项 | 核对结果 |
| --- | --- |
| 目标行为结论 | 三个真实 C++ 目标没有有效值矩阵，四组均 PARTIAL；两稿均没有把加载失败当 ABI 不兼容 |
| 计数单位 | 8 个 Native 最终 ELF 是编译/链接结果，不是运行通过数；shim 是 4 格 × 5 次 = 20 次，每次 5 内容项 = 100 项；额外绑定诊断不计矩阵 |
| 尺寸来源 | string 32/24、vector 24/24 来自独立 Boost 应用探针；没有冒称目标 provider 已测到这些尺寸，sizeof 相同不等于兼容 |
| 回调方向 | 插件调用引擎的 SetSyncBinaryReply 槽；不是 JS 直接传 vector，不是引擎调用插件接收函数 |
| 托管与原生 | C# 入口 C 形态与 binder/Dali 内部 C++ 操作分开；不从 C# P/Invoke 推出内部安全，不从内部 C++ 推出必然混库失败 |
| shim 范围 | 真实平台 Boost，不是模拟件；不同 C++ 修饰名分流，不覆盖 EWK 同名 C 符号；两侧本地销毁不冒称消费方直接销毁异库对象 |
| 普遍不可能性 | “单进程只能链接一套库”“两个项目无法任何双版本导出”“两个 TU 唯一可能”未写成事实；给出限定和来源 |
| 异常/取消 | 样本普通值通过不证明公共 ABI 支持库完全隔离，catch-all 样本不能原样用于取消；未验证范围两稿均显式列出 |
| 方案与工作量 | C 签名是设计，不是已实施；已定位文件/函数为下界；应用分母、完整工时及旧接口期限不推断补齐 |
| 双语一致 | 两稿均含四行总表、三个逐环事实链/已排除形态/可改变判断的证据、Native 限制、责任表与未覆盖范围；无新增推荐/排序 |
| 原始材料优先 | 使用实际头文件、ELF 输出与每次内容/maps 记录；上轮报告仅作范围索引，不充当新的行为证据 |

## 自动校验

由 [validate.py](validate.py) 检查 20 次原始退出码、每次 5 个 hex/长度/内容断言、maps 标记、作用域检查、四格各 5 次、8 个 Native 链接结果、相对链接存在性、英文中文残留、阶段 SHA256 以及两份预存 R115 脏文件是否未变。最终结果见 [VALIDATION.json](VALIDATION.json)。

自动校验 PASS 只说明这些检查一致，不是业务接口安全证明；不替代逐环核读。URL 原始访问日志与检索来源见机制报告，不将 HTTP 下载失败隐去。
