本次输入是冻结的两份限定名索引中 65 个 `COMPILE_TIME_ONLY` 候选的**全部行**：74,954 行。按“候选 + 文件 SHA256 + 行号”去重为 30,523 个位置；此前绑定 195 个，此次新增 30,328 个。继续按同一行的列位置展开，得到 31,586 处实际出现位置。RPM/架构重复行没有丢失，保存在各位置的 `references` 中；这些单位不能混加。

`COVERAGE_INVENTORY.tsv` 给每个候选的完整数量，`COVERAGE_AUDIT.tsv` 逐项断言冻结索引行均有处理结果。无超时截断，也没有 `samples[:3]` 处理上限。`inventory/` 保留原索引的行号与内容；`occurrences/` 保存实际表达式、实参、列号、上下文；`results/` 逐处保存结果与缺口。

**“全部处理”不等于“全部语义求解”。** 提取器是保留字符位置的词法解析器，不是完整 C++ 编译前端：无法解析、未选投影成员、依赖模板形参、局部别名与名字查找未闭合的地方都保留 `RESULT_UNRESOLVED`。未把处理过的未定项计作闭合。

## 类型判断的证据层次

1. 从平台头原文取闭合表达式，在两套库分别编译、各运行五次；保留具体类型、大小、空类/联合体等输出与布局记录。没有选取 `plan.json` 的人工实例。
2. `enable_if<条件, 明确结果类型>::type` 的结果类型可在条件成立时确定；本次测量该实际结果类型，不把条件改成 `true`，不声称平台已实例化该分支。相同两分支的 `conditional` 同理。
3. 部分 traits 的 `::value` 由两侧真实定义及布尔常量基类链确定为 `const bool`：这是静态核查，**不是具体谓词求值的实测**。实际条件值仍可未观测。
4. std 对象的指针/引用会同时检查指向的对象类型，不因指针本身是标量就关账。联合体的非静态成员另以布局输出核验，不单靠 `is_empty=false`。
5. 枚举、函数类型及其他非 std 类型不擅自归入用户给出的“内建/void/空类”三类；明确保留已测具体类型及分类疑问。
