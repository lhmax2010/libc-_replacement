# W2 `wbuffer_convert` 外部缺口补充

## 结论

`GAP_REMAINS`。本轮把 R11 冻结源码中此前未深扫、且没有 C++ ELF 指标的 965 个 source RPM 全部处理完；目标可见命中为 0。结合既有证据，R11 的 1,450 个冻结源码记录现在可按目标专项口径量化为 1,424 个完整覆盖、24 个部分覆盖、2 个上游源码不可得。但外部产品/应用组件的 BOM、最终产物、源码和重编声明仍全部 `NOT_AVAILABLE`，所以结论强度只能是“已覆盖范围内未发现使用者”，不能写成“平台上无使用者”。

## 2. 本轮补充手段与结果

### 2.1 965 个本地 SRPM

R90 的精确缺口为 1,105 条，其中 140 条已有 C++ 指标 ELF并由 R92 处理；余下 965 条压缩大小合计 3,168,053,995 bytes，对应 12,115 条已发布 ELF 记录，C++ 指标 ELF 为 0。965/965 个文件本地存在、下载状态为 PASS，本轮逐个复核冻结 SHA256。

执行采用单包生命周期、`nice -n 15`、`ionice -c 3`：展开外层 SRPM，安全展开 987 个内嵌 tar/zip 归档，以同一词法函数扫描 392,332 个源码、头文件和构建文本。925 包初始完整；40 包因归档链接目标不在已提取普通内容内而初始部分覆盖；外层或内层展开失败均为 0；目标命中为 0。

### 2.2 正向对照

正向对照把一条 `std::wbuffer_convert<...>` 使用放入 tar.gz，再经过同一安全归档展开器和同一扫描函数：1 个文件得到 1 条预期命中。独立 `rg` 用同一 token 边界规则再次命中。因此本轮零结果不是空规则、未展开归档或错误根目录造成的。

### 2.3 链接元数据复核

对初始 40 个部分包重新读取归档目录元数据并解析链接链：

- 571 个去重链接路径中，239 个最终落到归档内已扫描内容；
- 332 个最终目标不在归档；其中 31 个明确是 C/C++ 源路径，137 个无后缀、路径类型不能判断，164 个为明确非 C++ 路径；
- 18 个包的所有未闭合目标均是明确非 C++ 路径，按本次 `wbuffer_convert` 源码使用专项口径收口；
- 22 个包仍含 C/C++ 或类型未知的外部目标，继续记 `PARTIAL`。

初扫表中的 1,659 是 tar 内重复出现的链接成员次数；复核表的 571 是去重路径数，两者计数单位不同，不相互替代。R92 另有 `bcc-tools`、`chromium-efl` 两个部分包，共 9 个悬空目标，其中包含头文件或源码目录，因此仍为 `PARTIAL`。两个 `NOT_AVAILABLE` 是 `mic-bootstrap`、`qemu-accel`：SRPM 只有打包材料，没有已发布 ELF 所对应的上游源码。

## 3. 覆盖不到的分类、规模与使用可能性

### 3.1 冻结仓内仍有边界的材料

- 24 个部分 source RPM：已取得的内容都已扫描且命中 0，但缺失链接目标不能读取。22 个本轮无 C++ ELF 指标包对应的发布产物没有 C++ 指标，这降低了“已发布动态对象直接使用该 C++ 类型”的可能性；不能排除静态库、构建工具、测试、生成源码或完全被优化掉的使用。R92 两个部分包有 C++ 发布物，二进制层同样为零，但缺失源码仍不能推断。
- 2 个 packaging-only source RPM：二进制层已在 39,166 ELF 分母内，源码层实际构建来源 `NOT_AVAILABLE`。
- 宏展开、构建期生成、外部下载、完全内联/剥离或非 Itanium ABI 使用：现有词法源码与符号扫描都不能形成完备证明，规模 `NOT_AVAILABLE`。

### 3.2 外部产品/应用组件

外部产品镜像、应用商店包、供应商插件、现场下发组件和私有源码不在当前冻结仓清单内。它们的数量、语言版本、是否使用宽字符转换、是否静态链接以及是否随迁移重编均为 `NOT_AVAILABLE`。`wbuffer_convert` 常见于旧式 codecvt/宽字符流适配场景；没有外部材料时，既不能据其已弃用推断无人使用，也不能给出有意义的概率或有限上界。

## 4. 还需要的材料与提供方

若要把结论升级为“平台上无使用者”，需要产品集成/发布团队按产品 profile、架构和版本提供：

1. 最终产品 BOM，包含系统镜像之外的预装、商店、供应商、插件和运行时下载组件；
2. 对应的最终 ELF、静态归档及可加载模块，最好同时提供未剥离文件、DWARF、link map 或符号清单；
3. 组件源码、构建期生成源码、外部依赖锁定清单和编译数据库；
4. 每个组件在 libc++ 迁移中的重编/保留声明及旧版本淘汰策略；
5. 24 个部分包的缺失链接目标，以及两个 packaging-only 包的真实上游构建来源。

在这些材料到位前，外部真实分母和缺口上界均不能量化。

## 5. 结论强度与证据索引

可支持的表述：

> 在 R11 冻结源码的 1,424 个完整专项覆盖记录、24 个部分记录的可见内容、39,166 个已发布 ELF 和 8,911 个静态归档证据内，未发现平台调用方使用 `std::wbuffer_convert`。
