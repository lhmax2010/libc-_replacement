## 双语逐节核验

| 配对 | 一致性检查 | 结果 |
|---|---|---|
| API 概要／第二节 | 有限 C 样本、Engine/Rect NOT_OBSERVED、隐式 this；ICU 架构和断言；普通异常示例取消限定及释放协议 | 中英一致；英文未把条件性可行翻译成 measured safe |
| API 第三节 | 十行大小；原 deque 函数／元素／主动42；foreign 限定及77/12；智能指针风险 | 数字逐格相同；9组代码片段去注释完全相同 |
| API 第四至七节 | 转换协议不是不可能、不是每次复制；CEF/ICU条件来源；工作安排而非承诺；架构、四绑定、头重编、3/9/0因果 | 同一限定范围；英稿不是逐字直译但未增加成功承诺 |
| ABI 第一至三节 | 层一致不代表安全；size/align不代表全部布局；6057/1969/17口径及已核/未核 | 四稿数字表分别与原始表一致；中英用途／混配缺口一致 |
| ABI 第四至七节 | 原始树／已补丁状态、65/50/36单位、pthread后端机制、额外覆盖缺口、四绑定、项目原则 | 同一目标和边界；没有将更新DSO写成修复全部旧对象 |
| Chromium 两稿 | M16/M17 地址映射、S02 ABS含义、S03八/两处命名；其余原内容不动 | 两稿新增节仍各13 URL；57引用全改，五源码地址身份匹配；保留历史截止 |

三份英文稿的汉字范围扫描结果均为 0，有正向中文控制；不是用这一检查替代语义核对。
代码检查是语法-only，不链接、不执行；中文注释与英文注释允许措辞差异，但不改变代码行为。
