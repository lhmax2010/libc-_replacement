| 检查 | 结果 |
| --- | --- |
| 两候选原因是否分别有边界 | 原 BoundaryError 为类型匹配；另一夹具为 foreign；没有从 catch-all 单独归因 |
| LLVM 同侧失败是否保留 | 已保留，两稿均不再暗示混库是该失败的必要条件 |

| ARM 失败是否淡化 | 两稿表格明确 5/5 SIGABRT；C 缓冲区对照通过不能替代异常通过 |
| ARM 环境 | 本轮均 QEMU 用户态，非物理板；原物理板旧结果不冒充本轮内部轨迹 |
| 原始无效读参 | 保留初始记录，报告划定十次无效 RaiseException 头；以 personality 可靠读取为依据，不篡改原 stdout |
| 反向 EWK | provider NOT_AVAILABLE；矩阵 NOT_OBSERVED；未用模拟件或旧反方向 360 次补齐 |
| 新增转发层 | 反汇编链接逐架构给出；候选放置点明确标推论、未实测、取决于 dlsym 解析对象 |

| libsupc++ | 从延期移候选，有两架构实测，ARM 反例使整契约仍未闭合 |
| static_assert | 只评估位置和断言；24 字节 vector 大小检查不够、旧 ELF 不受保护、SDK 未定；没有实施 |
| 中英一致 | 核心事实、数值、四个新增节、架构、候选/推论限定一致；英文无中文残留 |
| 旧评审与材料 | 旧完整处置表和实验 2 不改，新表显式覆盖受影响条目；无改平台代码或配置 |

## 机器核对

[audit.py](audit.py) 复核结构化每格次数、具体值/清理与预期失败、库及快照 SHA256、中英新增证据链接集合、本地链接存在性、英文中文字符、原材料不变及两个开工前已有修改文件的摘要。结果见 [CHECKS.json](CHECKS.json)。生成归档两稿只将根目录相对链接机械改为归档目录相对路径，反向还原后逐字一致。

完整命令记录须含命令、stdout、stderr、退出码、起止时间，封存时逐项检查；[SHA256SUMS](../SHA256SUMS) 覆盖本轮新增证据与最终脚本快照。封存命令及后续 Git 交付记录因执行时序另存，不制造自引用摘要。

机器核对不能证明自然语言任意语义一致；人工已按上表逐项核对。历史快照的链接/排版不改。所有信号失败和早期编译失败的原 stderr 保留，不以报告脚本退出 0 代替底层程序结果。
