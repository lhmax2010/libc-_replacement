## 一、旧引用版本结论（已单独交审通过）

[实验 2 原报告](experiment2/REPORT.md)及其原始材料保持不变。冻结清单 39,166 行中未找到目标符号的普通 UND 导入；该零命中带实际 ELF 的正向对照。发现 18 个目标定义记录（六个真实组件、十二个 SDK 副本；十二种独立 ELF 内容），不能把定义数当独立应用数。

三架构真实转发库定义旧名，以 `dlsym` 按名找实现再间接跳转；当前目标导出没有命名版本节点。缺至少三个独立旧应用样本，故不能回答“所有已发布应用引用一定怎样”。**按旧 VERNEED 精确路由的前提没有在这些路径中取得；这不等于所有同 DSO 兼容门面都不可能。** 实验 2 已审阅通过，本轮不重跑或覆盖该阶段。

**零改动与方案 B：仍是有前提的设计问题，不是已确认可部署。** 业务问题须先明确旧 ELF 人群、零改动的含义及可允许的平台路由变化。新版第五节已按续任务增加“转发层的结构”：薄壳可作为转换层候选位置是**推论、未实测**，取决于 `dlsym` 找到哪个实现；反汇编只证明当前转发结构。没有把这一推论写成运行成功或替业务决定部署方案。

## 二、异常归因与配置对照

详见 [实验 1](experiment1/REPORT.md)。结论标为观测完成，**含失败，不是兼容性通过**。

| 核查 | 依据性质 | 结果及范围 |
| --- | --- | --- |
| 原 BoundaryError 退出 12 | 两架构实际函数落点和异常头，x86_64 原生、armv7l QEMU 用户态 | throw/personality 都是 libc++abi，LLVM 标识，确实进入类型匹配；同名 RTTI 身份不同，ARM 匹配返回 false。不是 foreign 路径 |
| 正向与干预对照 | x86_64，每格五次 | GNU 同侧成功；LLVM 同侧原导出条件仍失败；仅增加 export-dynamic 的受控跨库夹具捕获 77、guard=1，并观测 RTTI 地址合一。不是普遍链接建议 |
| foreign 候选机制 | 另一组版本隔离的 int 异常夹具 | GNU 标识实际进入 LLVM personality 并 catch-all；确认另一机制存在，不能移植成上述失败原因 |
| 历史 96 格 | 原构建静态核对＋每格五次复测 | 原来全部 x86_64，A/B 都用 libc++abi，不是两种 ABI 设置。480 次中同侧 240 次通过、跨侧 120 次 catch-all、80 次精确通过、40 次信号终止 |
| 真正 libcxxabi / libsupc++ 与两展开器设置 | 隔离构建＋两架构共 80 次程序运行 | GNU ABI 使固定样本在 GNU 展开器下两架构通过，x86_64 LLVM 预加载也通过；ARM LLVM 预加载却 5/5 SIGABRT。对应普通 C 缓冲区对照全部通过 |

`LIBCXX_CXX_ABI=libsupc++` 已从延期项移到**关键路径候选**，有实际构建和结果依据；**不能关掉整条异常契约**。ARM 反例尚未定位内部根因，版本/加载/配置及任意异常对象也未穷尽。没有将旧 libcxxabi 产物和新 libsupc++ 产物对比冒充排除一切混杂因素的单变量实验。

调试观测有一项纠正：初始十次 ARM LLVM RaiseException 断点过了序言，r0 读出的异常头无效；原记录保留并标 `INVALID_MEASUREMENT`。纠正后该函数的头参数仍 `NOT_OBSERVED`，但 personality 上的可靠头字节及实际函数所属库可用。具体无效范围、修正轨迹和普通运行的信号结果均在实验报告中说明，未把调试器退出码当程序退出码。
