## 标准条文与本次判断

D.21.2 第 3.2 段说明转换对象在 wbuffer_convert 销毁时释放，第 11 段的析构效果是
“The destructor shall delete cvtptr.”。该段未规定析构调用 sync/pubsync，也未规定缓冲容量、
构造后的 put 指针或三次单字符写入各自的即时字节输出量。
因此，**仅凭 D.21.2 不能要求析构把三个字符的九字节转换结果全部输出**。
这不是说条文禁止实现额外同步，也不是把任何丢数据行为都认定为符合标准。

## 最小用例覆盖与控制

[overflow_minimal.cpp](overflow_minimal.cpp) 沿用 P1 的文件流设计；只另加运行库 maps 身份检查和
十六进制打印。三次 sputc 都断言返回字符值，转换器先析构，再关闭底层文件流，最后读文件，
同时检查实际长度和完整 UTF-8 字节串。底层流关闭不会同步已经析构的转换器。

`explicit` 模式额外在转换器存活时调用 pubsync，并要求返回 0、完整九字节；它是验证
编码、输入、文件读写和测法的正向对照，不是篡改原测试来取得通过。
不覆盖原测试的 4095 缓冲大小、put 指针、pubsetbuf、直接 overflow、sgetc 读转换断言。
本次也不证明任意 facet、语言模式、架构或库版本。

裁决口径采用任务书明确规则：若 libstdc++ 同样不能满足原九字节析构输出预期，则接受
该已知行为变化。**这个口径不要求新 libc++ 与 libstdc++ 的实际输出字节数相等**；
报告必须另外列明数值差异，不能把“同样过不了”写成全部可观察行为相同。
正式三方结论以完成的五轮矩阵为准，不以静态分析或单轮预检替代。
