# 本轮验收口径

## RPM 格与文件数

两架构 × 三路径为六个验证格，不是强行要求六个 RPM 文件。每格保留实际产出的主包、static、common 及其他子包，逐个记录身份、大小、SHA256、RPM digest 与压缩参数。当前不做 x86_64 RPM。

libc++ 格检查主包实际依赖 libc++，static 仅静态纳入 C++/LLVM/BCC 等库、保留动态 libgcc_s；此处“static”不是完全无动态依赖。GCC 与未定义工具链两格的 static 文件与对应架构 Source1002 解出的原文件逐字节 SHA256 一致。

RPM 经 strip 后可能没有私有符号名。命名空间证据取本轮未 strip 的实际链接产物，并用 `.text` 与 `.rodata` 的逐段 SHA256 将它关联到最终 RPM 文件；不把 stripped 文件中搜不到符号写成不存在相应实现。

## 构建与安装边界

完整 `rpmbuild -bb` 必须正常完成，不能把已写出的部分 RPM 自动升级为完整构建。人工批准复用的 armv7l LLVM 18 个输入例外明确保留 `USABLE_BUT_BUILD_INCOMPLETE`；W2 再独立补做整轮。

私有构建根只允许本轮临时文件可写，原根及 codes/ 不改。安装后平台检查器保持启用。此前本轮遗漏其只读输入的失败按准备失误记录，不写为源码或标准库失败。

板上安装前先核对现有包、进程与本任务目录；不覆盖不明已有测试状态。正常 RPM 依赖检查失败时记录缺项，不使用 `--nodeps`、`--force` 跳过。若必须扩大到已有系统库升级，由人工确认，不借安装测试授权默许扩大。

## 功能与取消

RPM 通过不等于功能等价、也不等于允许替换发布资产。板上原件/候选须分别实际测试；不同版本、构建选项、内核能力、列举结果、脚本执行结果分别记录。

静态 libgcc 对照的预期崩溃只是待验证假设。若 armv7l 与 x86_64 表现不同，如实列出，不把预期写为观察值；同链接形态探针也不能证明来源未知且已 strip 的原二进制必然崩溃。

所有产物仍为 tmp/ 候选，不覆盖 Source1002，不推包仓。
