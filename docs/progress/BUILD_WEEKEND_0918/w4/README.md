# 周末编译适配验证记录

本目录仅记录候选构建与验证，不表示已替换发布资产。`codes/` 未改；候选保存在 `tmp/WEEKEND_0918/`，不推包仓、不覆盖 Source1002。

建议阅读顺序：

1. `STATUS.md`：当前阶段及尚未闭合项。
2. `QUESTIONS.md`、`ENVIRONMENT_CORRECTIONS.md`：待裁决问题，以及本轮输入/工具准备错误与修正；不能把这些错误改写成软件回归。
3. `ACCEPTANCE_SCOPE.md`：构建成功、RPM 产物正确、板上功能等价三者的区别。
4. 每格 `cells/<名称>/` 的执行日志及 `events.jsonl`，对应 `raw/` 内原始命令、开始/结束时间、退出码。
5. 各 `verify-*`、`audit-*`、`*-inputs.json`：最终产物与输入身份；只存在目录或日志不代表判据通过，要看结果和实际退出码。

RPM 的 `--checksig --nosignature` 在本轮用于检查包的摘要完整性，不声称做了 GPG 发布者认证。输入同时与既有固定记录的 SHA256 对照。`cp -a` 后核对常规文件 SHA256、符号链接目标、类型及模式；明确排除项见复制结果，不把排除项写为已扫描。

运行时取消测试的原始源码沿用已记录的同一探针；四种等待形式分别五次。测试预期不当作观测值，尤其不会把 x86_64 的静态展开器失败自动外推到 armv7l。

项目仓中的阶段归档若压缩了大日志，其 `MANIFEST.json` 提供解压后 SHA256 和原始长度。执行脚本快照与实际启动 SHA256 对照；事后恢复的快照明确标注恢复方式，不冒称执行前自动保存。

阶段归档无法包含其自身随后才产生的完成记录；这类归档、暂存自检、commit/push 回执在后续阶段材料中继续补档，不回填或伪造到更早的快照。
