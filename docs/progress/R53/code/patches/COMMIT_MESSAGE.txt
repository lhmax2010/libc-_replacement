libcxx: preserve forced unwind across library catch sites

libc++ library-carried iostream and istream catch-all handlers can consume
the foreign forced-unwind exception used by pthread cancellation.  Preserve
the existing stream state updates, recognize __forced_unwind before the
catch-all path, and rethrow it so cancellation can continue.

The change covers the two out-of-line ios state helpers, the explicitly
instantiated basic_istream members and their arithmetic carriers, and the
basic_ostream sentry destructor carried by libc++.so.  The corresponding
libstdc++ implementation catches __forced_unwind before catch-all and
rethrows after applying the same state transition.

This patch depends on libc++abi providing the compatible
__cxxabiv1::__forced_unwind type and the forced-unwind rethrow fixes.

Validated on x86_64 natively and armv7l hardware for cout, failbit,
basic_istream::getline and basic_istream::read cancellation paths.  The
library-only replacement path was checked without rebuilding consumers.
Selected iostream/future/string tests and the libc++abi regression matrix
were also run.  aarch64, LTO, concurrent cancellation and mixed-runtime
frame traversal were not covered.  The sentry destructor site is not
functionally observed because its implicit noexcept frame terminates a
forced unwind that escapes it.
