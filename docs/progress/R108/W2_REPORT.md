# W2 不随迁移重新构建的组件清单

## 结论

`PARTIAL`。平台已发布物和可得源码包内的三类候选已经量化，但外部产品/应用组件缺少 BOM、产物和重建策略，因而全局真实上界为 `NOT_AVAILABLE`，不能把已见文件数当成完整平台上界。

前三类数量不能直接相加：同一逻辑组件可能跨架构重复、静态归档与对象可能存在包含关系，源码包内残留也不等同于最终交付。由于第四类未知，全平台“可能复制旧实现”的有限真实上界无法成立。

## 符号检查解释

修正路径后，8,911 个静态归档中 1,600 个出现 Itanium C++ 符号，8,906 个可由 `nm` 正常读取；5 个异常分别属于 `golang-tests`（2）、`glibc-devel-static`、`app-rootstrap-devel`、`hal-rootstrap`，均保留在保守上界中。所有静态归档、源码对象和共享候选的目标实现可见命中均为 0。

目标符号不可见不能降低上界，因为内联、LTO、剥离、位码、格式不兼容和类型擦除都可能消除可见名字。C++ 指标也是工作性分类，不是“包含旧实现”的证明。

## 技术问题与权威表

- 首轮双遍目录枚举效率不足，主动中止并保留退出码 130；随后改为单遍枚举。
- 外部 I/O 负载一度触发资源门禁，退出码 21；W2 只读分析以 `nice 15`、`ionice idle`、并行 2 继续，构建门禁未被绕过。
- 合并清单首轮使用了错误的静态路径基准，导致 8,911 个静态项全部报告不存在。该段数据作废但保留；源码对象和共享候选段有效。
- `tables/w2_static_inventory.tsv` 与 `tables/w2_static_summary.tsv` 是静态归档的权威重跑结果；`tables/w2_inventory.tsv` 只用于其中两类源码候选。
