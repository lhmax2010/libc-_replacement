## 主要核对结果

- **33 / 10 / 23 及十个类型的字节数、差值均与原始探针一致**，但单位是具体模板实例的
  `sizeof`／`alignof`，不是全成员布局，更不是 ABI 等价性。原生探针 GCC 为 **13.3.0**，
  不是稿中测量环境所写的 GCC 14.2；后者是另一份平台源码的版本。
- **6,057 / 1,969 / 17 可从原始输入重放得到**。前者来自 GCC 源码内基线清单，后者来自
  平台 libc++ 的已定义导出文本；按去版本后的名字去重，不是两份当场实测库的纯 C++ API 个数。
  17 个精确同名项早已逐项核查标准层含义并有正确配对运行时的分组行为对照；混用兼容性仍未证明。
- **106884723786536 确有原始输出**。实际函数叫 `make_payload()`，元素为
  `{11,22,33,44}`，由 provider 销毁对象，consumer 主动返回 **42** 表示错值。
  稿中 `make_data()`／`{1,2,3,4}` 是改写，不能冒充逐字实验；错误长度也不是稳定预测值。
- **ICU 实验确实存在，但只有 armv7l 物理板的一次 `u_getVersion` 路径**，返回
  `78.1.0.0`，程序实际只断言主版本等于 78，并记录两套库加载。不是 ICU 全 API／业务验证。
- **异常反例确实存在于 x86_64 原生和 armv7l 实板**：libstdc++ 插件抛
  `BoundaryError{77}`，libc++ 接收侧进入 catch-all，退出 12。没有实测稿中的
  `EngineError : std::runtime_error`。不能写成所有库组合、方向、类型和绑定下一律接不住。
- **“纯 C++ 内置类型接口已经实测可支持”无对应 Engine／Rect 边界实测依据**。
  本轮 Engine 声明的语法检查通过，不是补做了跨库验证。
- **约 50 个 GNU 识别子句与我方 50 个保护站点不是同一单位**：固定 GCC 源树生产目录
  重数为 **65 个 typed-catch 句法点／16 文件**；其中 55 在 include，10 在 src。
  第一批补丁的 50 是保护站点：20 头侧＋30 库侧，实际新增 typed handler **36**。
- Chromium 两稿分别与本线既有中英文原稿 **逐字节一致**，没有搬运转述改义。
  **30 格 × 5 = 150 次**已逐条回查原始退出码、提供方身份和值／状态；
  40 次标记终止退出 86、100 次退出 0、10 次 SIGABRT（原始记录 -6），不能写成 150 次安全通过。
- Chromium 新增比较节的 **13 个唯一 URL 全部 HTTP 200**。全文两种语言的唯一外链集合为
  **36**，其中 **5 个返回 404**；本轮找回正确的 libcxx 分仓地址，五个下载内容均与原快照
  SHA256 相同。此外 HQ 目录缺附属材料，使 **中文 28、英文 29 处相对链接失效**，合计
  57 处引用、27 个唯一目标。

## 自行判断、疑问与边界

- 任务写的是三份报告；按三个主题核查 API 中文、ABI 中文、Chromium 中英文四文件。
  HQ 另有 API／ABI 英文文件，**不在本次逐段审阅范围**，若同批交付需同步修订并复核。
- 初查 Chromium 中文稿缺失，已询问；用户补入后读取并加入核对，缺件疑问已关闭。
- “不修改报告”与“输出修改建议”分别执行：修改仅限本核对目录；没有代改 HQ 或旧证据。
- 为核对代码语法，机械抽取示例并做 GCC 13.3 的 `-fsyntax-only`，加头文件控制单列，
  没有链接或运行任何新增 ABI／取消实验，没有占用开发板。
- 自行采用“typed-catch 源文本句法点”核对约数，计入无后缀标准头、宏形态及多行形式，
  剔除普通注释和字符串，带正向／负向对照；**不是 AST 全语义计数，不求预处理可达性或模板实例数**。
  不据 65 宣称存在 65 个实际取消点／缺陷／需要修改的站点。
- “已实测可支持”与“原则上有条件可行”区分，是证据分级，不是撤销或扩大支持政策。
  Engine／Rect 是否纳入最终外部支持承诺，仍由人工决定；本轮不代为认可。
- Chromium 八处／两处的确切清单从既有材料查到，见数字附录；没有自行推断为另两项缺陷。
- 原始实验的绑定／架构有限；没有重验产品二进制、全部第三方、性能、所有分配器或所有异常
  provider 顺序。“未找到该实验”只在列明的原始材料范围内记 `NOT_OBSERVED`，不宣称永远没有。
- 内部编号检查只针对正文的内部任务／规则标识；上游 LLVM 的 D106703 等是公开审查编号，
