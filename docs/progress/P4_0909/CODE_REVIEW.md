# 代码示例逐块核对

本轮没有修改报告代码。按原块机械提取至 snippets/，使用宿主 GCC 13.3.0、
C11／C++17、`-fsyntax-only -Wall -Wextra`；没有链接、运行或测试两套库互操作。
原样片段与“仅补通用头文件／前置声明”的控制分开，命令、退出码见 raw/syntax/。
语法失败与 ABI 反例是不同层次；伪代码不应当冒充完整程序，但也不把省略头文件等同于算法错误。

| API 原块／行号 | 原样语法 | 补头控制 | 语义与结论核查 |
|---|---:|---:|---|
| 1：C 接口头，29 | 1 | 0 | size_t 未声明，需 stddef.h（M14）。opaque handle 能隔离布局，但要同目标 C ABI、有效指针、生命周期、异常／取消与回调契约；仅签名不足证明安全（M01） |
| 2：Engine／Rect，56 | 0 | 0 | 合法声明，没有方法定义或跨 DSO 调用。隐式 this、完整类定义、构造析构、calling convention、pack 等仍影响兼容。**没有对应实测依据**（M01），不是“测过内置类型布局所以此类已安全” |

| 10：string→data/len→string，223 | 非编译语言块 | 不编译 | 是转换流程图，不是源码。两端显式转换可设计，裸地址还有借用生存期／编码要求；不证明所有转换必复制、异常迭代所有权都无法协议化（M08） |

原样执行总数是九个编译语言块×两个变体＝18 次语法检查；不要求它们全部退出0。
第2块本来就能编译，是本轮语法测试的正向对照；第1块加 stddef.h 后恢复，是缺头判定的正向控制。
第3、4块的 C++ 重载正向结果**不等于允许它们作为同名 C API 同时声明**。

## 安全性前提不能由语法检查完成

普通 C 头需要匹配参数大小、结构定义、对齐／打包、调用约定及符号声明。
opaque handle 须由拥有方创建并在模块卸载前按约定销毁；缓冲区须有效且长度、终止符与编码约定一致；
回调可能重新引入 C++ 异常或取消路径。Engine 的隐式 this 和对象初始化没有被33类型指标验证。
实际资源回收依赖正确分配／析构／deleter和取消清理，不能从一行“提供 engine_destroy”推成已验证。

这些是**条件性分析／静态规则核对**，本轮没有构造新的故障运行，也没有扩大支持范围。
修改文本集中在 FINDINGS.md 的 M01–M08、M14、S01，保持政策与技术必然性的区分。
