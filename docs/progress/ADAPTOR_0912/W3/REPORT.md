# adaptor 适用范围判据

结论：**CRITERIA_ESTABLISHED**，附逐接口判定。判据建立不等于所有接口实测完成。真实 EWK 已验证正常返回的状态转换；未得到真实 libc++ EWK、完整 browser receiver 或完成 Dali 图形初始化。没有证据把某整个接口族判为“任何 adaptor 都不可能”。

## 判据：必须同时满足，而不是按类型名一票通过

| 可检查的条件 | 能采用的中间协议 | 不满足或未知时的具体障碍 |
| --- | --- | --- |
| 跨界数据可完整枚举，编码/长度单位明确 | 标量、指针与字节长度；接收侧重建对象 | sizeof 一样不证明成员、allocator、指针有效期或行为相同 |
| 正常、失败、复用与部分更新规则已查清 | 输入旧状态、字段更新掩码或有条件提交 | 只传最终字段会丢旧状态；失败时无条件拷回临时零值会改坏输出 |
| 所有权与销毁方明确 | 借用期间复制；创建侧保留句柄及释放入口 | 对方 delete/realloc、shared_ptr 控制块、释放回调不能靠字节复制解决 |
| 所有入口/回调都能可靠路由到正确库 | 明确真实句柄与入口、分侧接口表 | 同名 C 导出、注册表、实例 ID、回调方向可能使转换被绕过或递归 |
| 双 TU 内部的同名定义不被错误合并 | 本地类型/命名空间区分；明确符号边界并检查产物 | EWK 初版实测：WEAK HIDDEN 析构在同一 DSO 内合并；仅 hidden 不够 |
| 异常与取消有可核的契约 | 各侧终结异常、错误协议、必要的本地重建 | 原异常类型、部分写入、取消强制展开不因 catch-all 自动保留；本轮未验证 |
| 不要求跨界保留内部地址/迭代器/引用 | 复制值，或句柄+访问操作 | 数据副本不保留原地址、失效规则、别名及零拷贝承诺 |
| 多态行为和对象身份可以留在原侧 | 对象不出原侧，远端句柄操作/回调代理 | 对象字节不是行为；虚表、RTTI、引用计数、线程亲和性需协议，不是一对 memcpy |
| 状态实例、线程/回调顺序可保留 | 稳定 instance 映射、销毁注销、序列测试 | 缓存 reply、未调用回调、重入、并发状态未知就不能只测单次输入 |
| 部署条件与 ABI 身份固定 | 真实双方组件、两方向、旧应用、链接/加载和打包验证 | 一种方向/优化配置的通过不能外推到 LTO、全局 preload 或不同产品 |

证据区分：前五项直接受已归档源码/实测支撑；后五项是根据签名、对象生命周期及已测覆盖**推导的检验要求**，不是本轮相应错误路径的实测结论。

## 逐个判定及可反驳的理由

| 接口/形态 | 判定 | 事实、尚缺及否证条件 |
| --- | --- | --- |
| ewk_parse_cookie 的正常返回值/字段协议 | **可行，限定已测方向及场景** | 同侧与修订原型在两架构 12 场景各 5 次一致；若同身份同输入旧状态下能复现正常返回字段差异，此限定结论失效 |
| ewk_parse_cookie 的完整透明部署 | **需进一步验证** | GNU→libc++ 未测；异常/取消、内部引用、加载替换与产品打包未验证；完成这些契约与矩阵才能提升结论 |
| SetSyncBinaryReply | **需进一步验证；数据转换结构可表达** | vector<uint8_t> 可按指针+字节长度在接收侧构造，再调用原回调；真实 receiver 还未跑。24 字节/三指针样本不证明跨库函数调用安全；若真实注册/instance/复制/返回/销毁双向全通过，可证实该协议 |
| binder 与 Dali 的已测 Property::Value 子集 | **已有直接混用的有限通过；不等于完整 adaptor 已可用** | 前轮实际源包装子集双向精确值/销毁通过；没有理由仅因发现 std 名称而把这组已测通过改成必败 |
| binder 与 Dali 的完整对象、Control/虚调用 | **需进一步验证** | 只换 core 的真实链缺 GNU vector 修饰名；本轮同侧离屏初始化未完成。需要实际对象身份、虚调用及所有权协议；成功属性子集不能补这格 |
| Native app_control.hpp 所选 SetOperation/GetOperation | **所选边无需额外标准库 adaptor** | 头文件与两种 ELF 显示本地 string 转 C 指针、C 入口；句柄销毁配对仍需契约。非全族运行安全声明 |
| Native app_common.hpp 所选 GetId | **所选边无需额外标准库 adaptor** | 所选平台入口 app_get_id 为 C；本地 C++ 对象不据此变成跨界对象 |
| Native service_app.hpp 所选 Run | **所选边无需额外标准库 adaptor** | 回调表与上下文 C 边；任意用户回调异常、线程与生命期没有全量证明 |
| Native app.hpp 所选 Run | **所选边无需额外标准库 adaptor** | 同前；已有八 ELF 是四包装×两库编译链接，不是八组运行矩阵 |
| Property::Value::Get(bool&) | **POD 转换条件性可表达，需验证** | 类型不匹配不写原输出；协议必须携带成功标记，失败保持原 bool |
| Property::Value::Get(float&) | **POD 转换条件性可表达，需验证** | 同理；还须同架构浮点表示及转换规则、provider 对象身份 |
| Property::Value::Get(int32_t&) | **POD 转换条件性可表达，需验证** | 同理；不假定本地零初始化即等价 |
| Property::Value::Get(Dali::String&) | **需进一步验证** | 失败保持，成功复制；Dali::String 不是 std::string，需按其真实数据/寿命接口编码，不可拿 std::string 布局套用 |
| Property::Value::Get(Property::Array&) | **需进一步验证** | 除失败保持外，还须递归属性类型标签、元素、嵌套、所有权规则；仅传容器内存不可接受为转换 |
| Property::Value::Get(Property::Map&) | **需进一步验证** | 同上，还涉及键的种类与映射语义；头文件不能单独生成完整语义 |
| Instance::SyncReplyToJS | **数据协议可表达，真实路径需验证** | 内部 string 赋值；保留实例、异常、旧缓存与随后返回路径 |
| Instance::SyncBinaryReplyToJS | **数据协议可表达，真实路径需验证** | SetSyncBinaryReply 的实际接收方法；不是额外一个已运行接口 |
| Instance::SendSyncBinaryMessageWithStringReply | **需进一步验证** | 输入字节/长度可表达；回调是否填回复、内部 move 状态与重入序列尚缺实测 |
| Instance::SendSyncBinaryMessageWithBinaryReply | **需进一步验证** | 同上且返回 vector；需要把结果搬回调用侧，不是只包装一次入参 |

静态补查 11 定义清单见 `../W2/STATE_SCOPE.tsv`，其中 EWK 与 receiver 在本表会按多个契约维度出现，**不得把表行数再当独立接口数量**。Native 证据见 `../../API_0911/W1/REPORT.md`，Dali 先前范围见 `../../API_0911/W1_CONT/REPORT.md`。

## “不可行”限定到具体形态

本轮已排除的不是 adaptor 这个机制，而是：

- EWK 只复制输入和最终输出、不带调用前状态的协议：真实负向对照每次只有 4/12 场景正确。以所有场景真实差分通过才能推翻此样本判定。
- 本轮初版的双 TU 同名包装类析构共存方式：实测析构错误。避免同名定义合并是已验证修正；不能仍把“只需两个 TU”作为充分条件。
- 不解析字段、直接把另一库 string/vector/多态对象的内存强转过去：这不是重建协议；EWK 直接混用已有故障。vector 或 Dali 的全部形态并无本轮必败证明，不能从 EWK 外推。
- 通用“指针+长度”若被解释成“复制一个带虚表/内部引用的对象的字节”不能满足原身份/虚调用契约。**推断、限定于该复制方案**；可保留原侧对象并用代理操作的方案未被排除，也未验证。

## 要写多少：可核的规模，不编造总工期

`raw/002_workload.stdout` 实际统计：EWK 修订实验协议头 8 行、GNU backend 26 行、libc++ front 22 行，共 **56 行**（包括注释/空行）；场景探针 49 行。不含编排、maps 归档、平台集成、安全错误协议与维护测试。不能报成“生产只要 56 行”。

| 可表达的范围 | 最小结构工作量（设计估算，非已实施包改动数） | 自动生成能做什么 / 不能做什么 |
| --- | --- | --- |
| EWK 已测单方向字段协议 | 一套 POD 头、两侧转换 TU；一入口、一真实 provider 寻址、一个四字段输出回调。反向须另一对分侧构建及独立测试 | 签名/字段序列化骨架可从头生成；缺省保留、拒绝输入、expiry、符号合并、异常不由头文件推出 |
| SetSyncBinaryReply 单回调 | 一对分侧转换函数，另需真实接口表注册适配、instance 映射与注销、回复获取验证；不是单独一个 vector 转换函数 | 可生 byte-vector 复制骨架；回调方向、有效 ID、生命周期与未回复语义需实现分析 |
| 三个标量 Get 重载 | 至少三组带成功标记的操作；若对象留 provider 侧，共用句柄身份协议 | 可生标量参数封送；失败保持与类型转换分支需规范/测试 |
| Dali::String Get | 一对长度/字节转换操作加失败标记，前提是取得真实字符串访问/编码契约 | 可生字节载体；编码、NULL/空串、异常、释放不自动得出 |
| Array/Map Get | 共享递归属性编码器/解码器，加两项操作；类型种类/图结构未审完，总行数 NOT_AVAILABLE | 可生已列类型分支；未知类型、对象身份、递归/循环处理不由裸签名得出 |
| Native 四种已选 C 边 | 新增标准库转换入口 0 个；仍需原生命周期/回调运行验证 | 零是“无需在已有 C 数据边重复转换”的结构判断，不是扫描零命中或零测试成本 |

完整 Dali 通用对象 adaptor 总量 **NOT_AVAILABLE**。局部范围检查仅看到 property-value-wrap.cpp 的 61 个 `SWIGEXPORT` 起始行、control-wrap.cpp 的 38 个，共 99；这是两文件导出定义起始行数，**不是 99 条跨库语义边，也不是每行都需改造**。有些只是标量，有些对象生命周期；不能按两个代表调用估全族人时。

每次调用的复制量可由协议检查：EWK 输入及初始四字段复制到 GNU，返回四字段复制到 libc++，另有 provider 自身操作；提交用 swap。延迟、峰值内存、分配次数的生产实测 NOT_OBSERVED。vector 协议至少在接收侧复制 n 字节；同步返回给另一侧通常再一次复制（取决于最终接口协议，推断）。不报未经测量的微秒/百分比。

维护：provider/API 团队维护状态契约；adaptor 维护者维护字段、类型、两侧符号/构建边界及错误协议；测试维护者在上游接口/布局/编译设置/回调表变化后重跑正反方向、旧状态、异常和生命周期矩阵。头文件生成只能减少机械工作，不能作为语义验收。

## 替代方案与承担者，不排序

| 方案 | 对当前障碍的适用性 | 谁要做什么与代价 |
| --- | --- | --- |
| 改成 C 数据接口 | string/vector 可暴露字节与长度；对象需句柄及操作/释放函数 | 平台新增/保留旧入口、定义状态/错误/所有权；应用开发者重新接入。Dali 对象/回调代理是重新设计而非改个签名 |
| 应用/相关组件改用 libc++ | 当源码和依赖可迁、双方构建/部署配套时，可消除该条标准库混用前提 | 应用和组件维护者重编并验证依赖；只迁 core 已有真实缺符号反例；是否有源码/可迁为业务信息，未推断 |
| 接受限制并声明 | 可把支持限定在同标准库/特定版本/已验证 C 边，不需要宣称通用 adaptor | 平台定义并维护兼容清单；外部应用需遵守依赖/部署要求；无法满足的二进制不在承诺内 |
| 完整 adaptor/对象代理 | 可保留调用侧接口形态的可能路径，但本轮只证明 EWK 字段协议 | 平台承担转换、注册、状态、生命周期与版本维护；未测部分不能写成已经可部署 |

这些是技术适用条件与代价，不作方案选择。是否接受异常契约变化、是否要求透明旧二进制及对外对象寿命，是待人工决定的合同条件；本轮不默认选择。
