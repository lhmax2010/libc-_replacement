# 后续候选的复用模板与验收方法

本批模板已经能区分“观测到不同”“固定样本相同”“不适用”“没测到”。**本批不是完整验证的达标样板**：真实包边界及全语言模式/全重载尚有缺项，不能只复制表格就声称后续 495 项做全。

## 每条记录必填

| 字段 | 要求 |
| --- | --- |
| 类型/具体实例、操作 | 写清模板参数、分配器、输入、语言模式；泛称 vector 不等于所有 vector<T> |
| 两侧源码 | revision、路径、行号/函数、配置宏，保留源码 SHA；实际编译头与只读树不同要附 diff |
| 最小程序 | 每个检查项目独立程序，共同的日志/注入辅助头也须快照；一个程序内的多个输入不能算多个独立边界 |
| 构建格 | 架构 × 标准库 × 配置；命令原文、输出、退出码；链接失败与运行失败分开 |
| 运行格 | 每格 5 次；值、长度、字节、分配次数、状态与销毁检查；不打印一个 OK 代替结果 |
| 正向控制 | 同一公开签名/真实组件的同侧控制；控制失败则不能归因于跨库 |
| 身份 | 头版本、ABI 配置、运行库哈希；maps 解析最终文件名，不以路径里出现“libc++”判断加载了 libc++ |
| 结论 | 差异 / 固定样本无差异 / 不适用 / NOT_OBSERVED / NOT_AVAILABLE；列出会改变结论的配置 |
| 开发者说明 | 哪类代码受影响；只依赖标准保证时是否要改；有哪些替代写法 |

## 可复用命令

在本工作区，顺序运行：

```bash
python3 docs/progress/R118/code/run.py string --arch x86_64
python3 docs/progress/R118/code/run.py string --arch armv7l
python3 docs/progress/R118/code/archive.py string
python3 docs/progress/R118/code/audit.py
```

将 string 换为 vector/function 可跑相应基础矩阵。脚本只使用既有工具链/库，并不会下载材料或在平台源码树构建。目标源码位于 `code/<type>/`，临时执行文件位于 `tmp/R118/<type>/`。ARM 每轮核对独占上传目录不存在，逐项上传、核验 SHA、执行、删除确切上传件、rmdir 验证；连接或结束标记异常即抛错，不再重试或清理。**重跑前仍须按使用方资源/板子协调规则检查**，这些命令不是无条件抢占授权。

工具链路径集中在 run.py；迁移到其他工作区须按真实材料显式更新路径，不应忽略不存在的依赖。临时目录固定名仅适用于本次独占执行，不能让两个会话共用。归档文件名冲突采用 attempt 后缀保留旧记录，不覆盖原始失败证据。JSON 数值附录是每格最新一次矩阵；老 raw 留存供追查。

## 验证方法的限制

1. 五次重复是固定输入和固定配置的重复性检查，不是总体置信区间。标准允许不同的 capacity、hash 或 compare 具体值，要与错误区分。
2. 私有成员、位域、非标准布局不能靠可移植 offsetof 任意获取。本批使用目标编译器布局和公开对象行为；静态偏移与运行值分别标注。vector 三个端点必须使 size 与 capacity 不同才能从值区分。
3. 不解引用失效迭代器；保存整数地址的变化不能单独证明迭代器契约。
4. new 注入检查“该失败点传播什么、对象是否保留”，不是操作系统耗尽内存，也不是任意元素/分配器的保证。function 小对象阈值必须至少包含尺寸、对齐、拷贝性质与销毁。
5. 不强制 dlsym 另一修饰名后声称自然链接放行；若做强制调用，另立压力实验并注明方法。本批真实 Boost 混合格自然链接失败，EWK 同名入口则运行崩溃，不能合并成一种现象。
6. 真实回调宿主的注册、初始化和事件循环是前置；GNU 同侧控制失败不能写成跨库不兼容。本批 LWE 的原始失败均保留。
7. R117 单侧解析命中只能产生接口候选；实际编译反证与对应正向控制后才升级。两个库都没有的接口不能计成库间差异。

## 工作量校准

实际阶段起止见 [TIMINGS.json](TIMINGS.json)，含扫描、编码、构建、实测、材料整理；function 截止点是提交前自检，单独标明。构建执行使用已有产物，未重建标准库或浏览器。三个阶段均为 PARTIAL，**不能把这些用时直接乘 495 当作完整验证预算**。后续估时应分别记录基础程序、跨架构准备、真实提供方/宿主准备、异常及销毁四部分；真实组件前置通常不是简单按类型数线性扩展。

## 本次自检特别事项

基础 identity() 的文本采集采用宽子串，因此路径 `libc++_replacement` 会使非标准库的映射也被打印。原始映射未丢失；独立 audit.py 按实际共享库文件名再次核对，**不把宽匹配行数当加载库数**。这项方法约束保留给后续模板使用者。

审阅顺序：先看各类型“未覆盖”，再看每条源码/输入/结果，最后看开发者说明；不要仅依赖概要中的项目数。
