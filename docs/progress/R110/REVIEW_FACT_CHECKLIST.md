# libc++ 运行时迁移事实核对清单

本清单用于评审时逐项核对材料是否被准确引用。勾选表示“证据与表述一致”，不
表示接受对应方案，也不构成优先级或推荐。

## 证据口径

- [ ] 所有零命中结论都写明了扫描分母，并能找到正向对照。
- [ ] `NOT_OBSERVED` 只表示未实际观测，没有被改写为“不存在”或“安全”。
- [ ] `NOT_AVAILABLE` 同时写明了缺失材料和无法成立的全平台结论。
- [ ] QEMU user 结果没有被表述为物理目标板、目标内核调度或设备路径结果。
- [ ] “符号能链接”“进程未崩溃”“值正确”“析构完成”四类判据没有互相替代。
- [ ] 推断均标注了前提，没有伪装成运行时实测。

## 条件变量普通错误策略

- [ ] libc++ 未持锁检查会生成 `EPERM` 的 `system_error`。
- [ ] 底层等待的非零、非正常超时返回会生成对应 `system_error`。
- [ ] 保留规格时，未持锁和注入 `EINVAL` 在 x86_64 各 5/5 终止。
- [ ] 解除规格并重编后，两格各 5/5 得到具体 `system_error`，code 分别为 1 和 22。
- [ ] 旧调用点加载新实现仍各 5/5 终止。
- [ ] 受控 `EINVAL` 只证明传播形态，没有被当作产品自然发生证据。
- [ ] 92 条直接可归因源码调用与 311 条未决词法候选被分别表述。
- [ ] 生产范围的 8 条直接调用均有持锁依据，但没有扩写成全平台无违规调用。
- [ ] 601 个发布消费记录全部进入既定重编计划，且限定为可见 out-of-line 调用。
- [ ] libstdc++ 没有对应普通错误检查，这一点没有被当作安全先例。
- [ ] libstdc++ 未持锁返回后的库层/native mutex 所有权不一致已明确写出。
- [ ] 保留与解除异常规格的收益、损失和异常被吞的可能性均陈述，未作选择。

## 已编译调用方与交付

- [ ] 顶层 `noexcept` 不改变目标函数自身的 Itanium 名字，但改变函数类型和调用方
      展开/清理元数据。
- [ ] 普通等待和 system-clock helper 是 out-of-line 动态符号。
- [ ] steady-clock helper、generic Clock 模板、`wbuffer_convert` 析构是头文件内联
      实现，库更新不能修正旧对象中的这三处。
- [ ] 独立 `.symver` 探针只证明机制可表达，没有被写成真实 wrapper 已完成。
- [ ] libstdc++ 只对公开普通等待保留旧、新双版本；内部定时实现没有相同双符号。
- [ ] C++03 兼容头镜像被计入实际变更范围。
- [ ] 不重编候选的四类分母没有相加成虚假的全局上界。
- [ ] 5 个确认只复制安装的共享 DSO没有被推断为一定调用或一定不调用目标路径。
- [ ] 外部旧对象和内联实例分母仍为 `NOT_AVAILABLE`。
- [ ] 直接替换、符号双版本加内联点重编、保持现状的后果均列出，未选方案。

## `wbuffer_convert` 析构收尾

- [ ] 该析构是因虚基类契约而隐式 non-throwing，不存在可单独删除的显式标注。
- [ ] 派生析构单独放宽异常规格的编译拒绝已有探针验证。
- [ ] 析构同步会进入用户 codecvt 和 wrapped streambuf 的开放虚调用。
- [ ] 保留同步可能完成输出收尾，也保留异常/取消终止边界。
- [ ] 停止析构同步可能丢失转换尾部或缓冲数据，没有被描述成无代价。
- [ ] 显式 close/sync 协议只影响重编且完成调用点迁移的消费者。
- [ ] 扩大 `basic_streambuf` 析构契约的影响被写为整个派生层次，而非单模板改动。
- [ ] libstdc++ 默认析构不调用 sync 的事实只作为实现对照，没有替代产品需求。
- [ ] 1,450 个 source RPM、11,332 个 binary RPM、39,166 个 ELF、8,911 个静态
      归档的零命中都有正向对照。
- [ ] 零命中结论写成“冻结覆盖范围内”，没有写成“平台上无使用者”。
- [ ] 外部产品 BOM、源码、重建策略和自动收尾依赖均仍为 `NOT_AVAILABLE`。

## Boost 跨运行库边界

- [ ] 90 条边、13 个 consumer source package、75 个架构/ELF 路径的口径未混用。
- [ ] 63 条布局敏感与 27 条 ABI 耦合但布局未证明之和为 90。
- [ ] “布局未证明”没有写成“布局安全”。
- [ ] 累计实测是代表符号组口径的 49/90，剩余 41 条保持未观测。
- [ ] 已测布局敏感为 33/63，未测 30；已测布局未证明为 16/27，未测 11。
- [ ] x86_64、armv7l QEMU user、aarch64 QEMU user 的结果分别标注，没有跨架构
      填充。
- [ ] 每个新增 aarch64 混合格 5 次，并有同 provider 的 libstdc++ 正向对照 5 次。
- [ ] `/proc/self/maps` 对混合格确认 libc++、libstdc++ 与真实 provider 同时加载。
- [ ] Filesystem 和 Boost.Test 的静默错值没有因析构完成而被判安全。
- [ ] aarch64 Program Options 的值正确、析构退出 139 两阶段均被记录。
- [ ] Boost.Thread 的精确通过只限单线程 once 状态样本，没有外推整个 provider。
- [ ] 同运行库正向对照通过只证明测法有效，没有被写成全 API 安全证明。
- [ ] 协调同运行库重编、C ABI/句柄适配、并行 ABI 产物、进程隔离和接受现状的
      后果均列出，未作推荐。

## 共同事实与架构边界

- [ ] 五处之外的 `atomic<int>::wait` 正交探针只标为 x86_64 实测。
- [ ] 补丁 libc++ 与系统 libstdc++ 各 5 轮，正常对照 5/5、取消判定 25/25。
- [ ] 两个异步取消组件只写成“条件可达”，没有写成所有产品工作负载固定必达。
- [ ] 处理已知五处不会自动保护这两个组件的结论已单列。
- [ ] aarch64 QEMU 装载试跑只证明执行环境和生命周期子集可用。
- [ ] aarch64 的线程取消、信号时序和真实目标内核行为仍为 `NOT_OBSERVED`。
- [ ] 外部组件缺口被明确说明会同时影响调用方重编、模板使用和 Boost 边界闭包。
- [ ] 材料没有对四项待决事项作推荐、排序或最终决定。

## 交付完整性

- [ ] 背景材料中的可复核链接均能打开。
- [ ] 原始命令、stdout、stderr 和退出码均保留。
- [ ] 本轮所用脚本快照及 SHA256 已纳入清单。
- [ ] 平台源码、既有四个补丁和只读源码区未被修改。
- [ ] 本地提交已形成；远端推送成功，或失败原因与所需人工动作已如实记录。
