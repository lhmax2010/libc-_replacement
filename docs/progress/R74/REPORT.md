# R74：对外报告复现用例实际验证

日期：2026-08-28

## 1. 结论摘要

报告最新版特征门禁全部通过：共七个问题；问题一含 `#if defined(__GLIBCXX__)`；问题五含 `CancelAllocator`；测试数量写作单一构建 10,320 项、两种构建合计 20,640 次执行；第七节已说明 D-01 在前文详述，随后唯一列出 D-02 至 D-25 共 24 项；无 `R66-XXX`。

报告中的复现代码**并非每段都能让读者原样照做并得到所述结果**：

- 问题一完整可编译，x86_64 与 armv7l 的核心对照均稳定复现：libstdc++ 5/5 退出 0，libc++ 5/5 退出 134。不过 libc++ 侧两架构都未观察到报告表中的 `EVENT destructor`；伪终端观测为 `EVENT catch_all` 后直接 `FATAL: exception not rethrown`。
- 问题二原代码缺 `<iostream>`、`<pthread.h>`、`<unistd.h>`，原样不能编译。只补这三个头文件后，两架构均稳定取得 libstdc++ 0、libc++ 134。
- 问题三原代码缺头文件、`waiter_started` 和 `some_work`，原样不能编译。补齐后，两架构均稳定取得 libstdc++ 0、libc++ 134。
- 问题五原代码可编译，但 x86_64 两套标准库都是 5/5 退出 0、`PTHREAD_CANCELED`，与报告声称“两套库都终止”相反。调试栈直接显示第一次 `allocate(1025)` 来自 `CancelString s(1024, 'x')` 的构造；取消在构造期送达，控制流没有到达 `reserve()` 或 `shrink_to_fit()`。

因此，四段标为复现步骤的代码中：一段原样支撑核心结论但有一项输出不符；两段需补全后才支撑核心结论；一段原样运行推翻报告所述结果。

## 2. 提取与编译

共提取 11 个 `cpp`/`c++` 代码块并逐字节保存。4 个是复现用例，7 个是说明性或上游源码节选。所有 11 块均按两套标准库尝试独立编译：只有问题一复现块和问题五复现块原样编译通过；其余 7 个非复现节选本来就不是完整翻译单元，问题二、三两个复现块则属于报告缺失必要内容。

逐块结果见 `tables/code_block_results.tsv`；原始编译诊断见 `raw/raw_compile/`；补全内容和逐行 diff 见 `supplemented/` 与 `raw/032_supplement_06.diff`、`raw/033_supplement_09.diff`。

报告给出的 GNU 命令可用。报告给出的 `clang++ -stdlib=libc++` 在当前宿主不能原样执行，因为 `clang++` 不在 `PATH`。实际 libc++ 编译使用项目既有包装器，完整选项在各编译日志；运行使用 R68 的未打补丁基线运行库，`ldd`、`LD_DEBUG=libs` 和库 SHA256 均已保留。

## 3. 运行矩阵

完整矩阵见 `tables/reproduction_results.tsv`。每个适用格运行 5 次，没有出现时通时不通。

armv7l 只运行报告明确声明“两种架构一致”的问题一、二、三；问题五按报告声明只在 x86_64 运行。板端使用独立目录 `/opt/usr/home/owner/share/tmp/r74_20260828`，没有触碰另一任务的板端材料；收尾只删除该目录并核验不存在、R74 进程数为 0。

问题五的调试器现场见 `raw/problem5_debug/libstdcxx.gdb.stdout`：`CancelAllocator<char>::allocate(n=1025)` 的调用栈依次经过 `basic_string::_M_construct` 和字符串构造函数，然后才到 `worker` 的构造语句。该直接证据解释了为什么当前用例只能证明“自定义分配器构造期间可取消”，不能证明取消穿过 `shrink_to_fit` 的不抛异常边界。

## 4. 代码引文

7 处文件/位置都能定位到对应实现，核心机制转述基本相符，但**没有一处可以整体视为逐字引文**。详细结果见 `tables/source_quote_results.tsv`。主要问题：

- `eh_personality.cc:563-573` 的块省略实际第 570 行注释，却又包含实际第 575 行 `else`，标称行号范围不成立；
- `ios.cpp` 节选没有行号，并省略 `_LIBCPP_HAS_EXCEPTIONS` 条件编译；
- `condition_variable.cpp:33-37` 用省略号替代函数尾部，实际完整错误检查延伸到第 38 行；
- 其余引文有格式压缩或报告添加的中文注释。

## 5. 数字

任务指定数字中只有一项与工作区原始材料不一致：报告写“10 个源码包 / 8 个包名 / 45 处独立站点”，R32 的实际结果是 **10 / 8 / 50**，并明确说明“不重算 R1 的 45”。其余指定数字均能由既有材料支撑。逐项结果和来源见 `tables/numeric_results.tsv`。

## 6. 外部链接

五个链接经浏览器均可访问，内容与报告对应转述相符。命令行 `curl` 对 libc++、Chromium、Android 返回 200；GCC 邮件归档两页返回 403，但浏览器访问成功并能读取正文，因此登记为“浏览器可访问、curl 受站点策略拒绝”，不登记为失效。详情见 `tables/external_link_results.tsv` 和 `raw/external_links_exact/`。

## 7. 不一致清单（按严重度）

1. **严重：问题五复现逻辑没有命中声称的函数。** 两套库实测均干净取消；调试栈证实取消点首次出现在字符串构造，不在 `shrink_to_fit`。
2. **严重：问题三复现块不是完整程序。** 除头文件外还缺两个具有行为含义的定义，读者不能原样运行。
3. **较高：问题二复现块缺三个必要头文件。** 读者原样编译失败。
4. **较高：问题一 libc++ 输出序列多写了析构事件。** 两架构和伪终端均未观察到该行；退出 134 和 FATAL 则稳定复现。
5. **较高：影响面站点数把 R1 的 45 与 R32 的 50 混用。** 10 包/8 包名这一口径对应 R32 时应写 50。
6. **一般：多处源码引文是经过编辑的节选，但标注方式像逐行源码引用。** 个别行号范围和实际内容不一致。
7. **环境依赖：报告的 libc++ 编译命令假定系统有可直接使用的 `clang++` 与 libc++。** 当前宿主不满足；本轮必须使用项目包装器和明确运行库路径。
