## 问题一：线程取消会被 `catch (...)` 吞掉，导致进程终止

### 先说明一个背景机制

程序里有一种操作叫「终止一个正在运行的线程」（`pthread_cancel`）。它不是粗暴地把线程杀掉，而是让线程**有序退出**：从线程当前位置开始，一层层往回退，沿途执行每一层的清理代码（析构对象、释放资源），最后线程干净地结束。

这个「一层层往回退并清理」的过程，在 Linux/glibc 上叫**强制展开**（forced unwind），它和 C++ 抛出异常时发生的事情**用的是同一套底层机制**。

### 问题是什么

因为机制相同，下面这种非常常见的写法：

```cpp
try {
    // 这里可能有取消点，例如读写、等待
} catch (...) {
    // 捕获所有异常并处理
}
```

**会把「线程终止」也一并捕获**。捕获之后如果不重新放行，终止流程就走不完，glibc 判定出错并**终止整个进程**，打印：

```
FATAL: exception not rethrown
```

### 两套标准库为何不同

**libstdc++ 提供了一个专门的标记类型**，让代码能识别出「这是线程终止，不是普通异常」：

```
codes/gcc/libstdc++-v3/libsupc++/cxxabi_forced.h:48-54

  class __forced_unwind
  {
    virtual ~__forced_unwind() throw();
    virtual void __pure_dummy() = 0;   // 纯虚函数，使该类不可实例化
  };
```
