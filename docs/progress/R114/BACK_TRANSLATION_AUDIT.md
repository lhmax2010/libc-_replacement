# 英文清单随机回译核对

## 抽样方法

以 Python `random.seed(20260904)` 对 254 行做无放回随机抽样，得到以下 10 包：

`coreutils`、`findutils`、`libmd`、`gzip`、`sed`、`ncurses`、`giflib`、`qemu-accel`、`python3-mako`、`meson`。

抽样命令及名单见 `raw/028_select_backtranslation_sample.*`；每行的中英文完整理由及判定并排记录见 `raw/029_backtranslation_sample_material.stdout.txt`。

## 逐行回译结果

| 包 | 英文独立回译后的核心内容 | 与中文原文比对 |
|---|---|---|
| `coreutils` | 仓库摘要保持原文；三架构四类载体均未命中；revision 命中至少一份设备镜像；在所述检测边界内没有需选择标准库的 C++ 构建/交付边界。 | 一致，限定词保留 |
| `findutils` | 仓库摘要保持原文；三架构四类载体均未命中；revision 命中至少一份设备镜像；在所述检测边界内无需加入标准库切换。 | 一致，限定词保留 |
| `libmd` | 仓库摘要保持原文；四类载体均未命中；revision 不在六份镜像清单；结论仅限定在已声明检测边界。 | 一致，未把“未命中”译成“绝对没有” |
| `gzip` | 仓库摘要保持原文；四类载体均未命中；revision 命中设备镜像；没有已识别的 C++ 构建/交付边界。 | 一致，限定词保留 |
| `sed` | 仓库摘要保持原文；四类载体均未命中；revision 命中设备镜像；无需标准库切换。 | 一致，未省略证据范围 |
| `ncurses` | 自身部分 ELF 依赖 libstdc++；armv7l 的 Unified 调用方仍为 `aspell`、`parted`、`pass`、`psmisc`；共享符号为 C 接口，其他已分析边无 C++ 符号交集；Base 内部也仅 C 接口；revision 命中设备镜像；因此已测边界不依赖 C++ 对象布局、异常或析构。 | 一致，调用方、架构、接口分类和结论全部保留 |
| `giflib` | 仓库摘要保持原文；四类载体均未命中；revision 命中设备镜像；结论限定于本方法覆盖范围。 | 一致，限定词保留 |
| `qemu-accel` | 实际构建日志有 C++ 动作；无 C++ 头文件载体；直接运行时依赖为 `NO`，静态归档计数为 0，armv7l 到 Unified 的 C++ 边为 0；revision 不在六份镜像；C++ 仅在构建过程或非运行时载体出现。 | 一致，两个 `0`、`NO`、架构与边界均保留 |
| `python3-mako` | 仓库摘要保持原文；四类载体均未命中；revision 不在六份镜像；在检测边界内无需标准库切换。 | 一致，限定词保留 |
| `meson` | 仓库摘要保持原文；四类载体均未命中；revision 不在六份镜像；在检测边界内无须选择 libc++/libstdc++。 | 一致，未把阴性证据扩大为源码绝不含 C++ |

## 结论

10/10 行回译后与中文原文语义一致；没有发现限定词丢失、肯定程度增强、数字变化、包名/路径/符号名改写或判定变化。

另对 12 个覆盖不同理由模板的定向样本进行了完整中英文并排复核，记录见 `raw/027_translation_sample_review.stdout.txt`。该定向复核不是“随机 10 行”的替代，而是对随机样本类别分布偏窄的补充。
