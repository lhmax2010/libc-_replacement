# 自行判断、限制与待人工确认

## 本轮自行判断（均未改变用户判据）

1. 采用允许的 Clang + libstdc++ 作为 GNU 对照，以保持 compiler driver 不变；
   GNU 标准库/libgcc 版本实际来自 14.2.0 RPM，而不是把 driver 说成 GCC。
2. 链接选项的单变量修正仅需重链接一个目标，复用未改变的对象及静态库；
   未从头编译，不改上游 C++。另做了静态 GNU 标准库＋动态 libgcc 的 20 次验证。
3. 原资产中的 personality 字符串不能单独识别展开器实现，故保持未定；
   不制造“与未知原配方相同”的探针，也不据当前 x86_64 结果推断原 ARM 程序必崩。
4. 未把 LLVM 全树的取消命中全部归给 bpftrace；区分 OpenMP 条件、FreeBSD/Mac
   LLDB、sanitizer、测试，以及候选 map 的实际输入。
5. 只有本轮覆盖配置/等待形态可以称失败机制已消除，不把根治验证写成全平台保证。
6. 上游精确关键词未找到同机制 bpftrace 故障、musl/AppImage 形态又不同，故未写
   一份宣称官方产品已崩的 issue，未对外提交。是否做配置适用范围的上游讨论由人工定。
