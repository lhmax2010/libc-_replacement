## 自动检查与手工检查的边界

`raw/018_document_check.*` 的退出码为 0：既有受跟踪材料 SHA256 未变；两稿本地链接存在、代码围栏闭合、英文无汉字、去掉链接目标后正文无内部任务编号；中英 C 代码块与原设计一致；根目录副本同内容；上述 EWK 原始数字断言通过；处置编号唯一连续。

检测有正向对照：人为含汉字、内部编号的字符串能被识别，不存在的本地目标能被识别。**链接存在不等于已证明引用语义正确；处置编号连续不等于机器证明无漏意见**。语义覆盖由本轮对照完整评审的逐行处置表申报，不能说自动工具证明了全部判断。

本轮没有新增外网资料结论或重新验证网页时效。正文链接主要指已归档的本地证据；外部先例只作为待后续核查的评审线索，原URL保留在完整评审快照。没有把网页可达性检查冒充平台实验。

暂存后全范围 `git diff --cached --check` 返回 2，原因是原始评审结尾空行、带行号的原始 stdout 和原文 diff 中的空白；不修改这些证据来消除格式告警。对新写中英文正文、处置表、自检及脚本单独检查退出 0（`delivery/005_authored_format.*`）。原始 `git diff --no-index` 退出 1 表示旧/新稿有差异，不是读取失败。

## 原始命令、快照与边界

`raw/` 记录材料定位、读取、数字/绑定回查、归档压缩及自检命令的可执行原文、stdout、stderr、退出码和起止时间。文档通过 apply_patch 写入；最终文档快照与根目录旧/新 diff 供复核。`audit.py` 只归档输入并检验文档/哈希，不构建、不运行平台探针；其源码和 SHA256 随材料提交。

`evidence_before.json.gz` 为冻结时的完整受跟踪证据哈希清单，使用 gzip -n 无时间戳压缩；不是重写原始实验。`inputs/` 保存用户评审、旧稿、正式底本和既有记录器的字节快照及来源摘要。

P10 不要求构建资源闸门，实际仅做文档与只读材料核对；大量哈希检查使用 nice 15/ionice idle。没有使用开发板，没有修改 codes/config、平台补丁或运行库，没有外部消息/评审提交。
