Hi Dongkyun,

Let me explain how "distinct sites" is obtained, and — while preparing this
— we found that the figure of 50 in last week's report was inaccurate.
Please let me give you both the method and the correction.

---

**1. Definition**

A "recognition clause" is a `catch` (or libstdc++'s `__catch`) clause that
catches `abi::__forced_unwind` or `__cxxabiv1::__forced_unwind`.

A "propagating site" additionally requires the handler to re-propagate,
either by a bare

```cpp
throw;
```

or by libstdc++'s `__throw_exception_again` macro.

A **site** is identified by the triple: **source RPM instance + path inside
the package + line number**.

---

**2. How to reproduce the count**

Step 1 — unpack the source RPMs and search for either spelling of the type:

```
abi::__forced_unwind
__cxxabiv1::__forced_unwind
```

Step 2 — for each hit, open the file and confirm it is **an actual catch
clause**, not a mention inside a string or comment.

Step 3 — check whether the handler re-propagates. Note there are **two
forms**:

```cpp
catch (abi::__forced_unwind&) { throw; }
__catch(__cxxabiv1::__forced_unwind&) { __throw_exception_again; }
```

Step 4 — count one site per file+line.

Step 5 — deduplicate: the same package may appear as several source RPM
instances (different Release versions), so collapse those to package names.

---

**3. The correction to last week's figure**

| | Reported | Actual |
|---|---:|---:|
| Sites | 50 | **104** |

The original scan had two defects:

- **4 false positives** — in `key-manager`, log message strings containing
  the type name sat next to a real catch and a `throw;`, and the heuristic
  matched them;
- **126 missed** — the original scan only recognised a bare `throw;` as
  re-propagation, so every site using `__throw_exception_again` was skipped.
  The file-extension whitelist also excluded extensionless C++ headers such
  as `future`, `ostream` and `condition_variable`.

Re-counting the same frozen snapshot without those restrictions:

| Measure | Count |
|---|---:|
| All recognition catch clauses | 175 |
| Of which re-propagate | 172 (46 bare `throw;`, 126 macro form) |
| **After deduplicating RPM variants** | **104 logical sites** |

**On the package count**: "10 source packages, 8 after deduplication" — the
10 counts source RPM instances; the duplicates are different Release
versions of GCC and TensorFlow2.

---

**4. If your numbers differ**

The most likely causes, based on what we found in our own scan:

- whether the macro form `__throw_exception_again` is included;
- whether extensionless C++ headers are searched;
- whether string literals and comments are excluded;
- whether RPM variants of the same package are deduplicated.

The per-site list (package, file, line, actual code line) is attached so you
can align directly against your codegrok results.
