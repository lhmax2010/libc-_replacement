# 范围与判据

继承 [S_R119_20260918 与 S_A](../R119_RECLASSIFY/SCOPE.md)。只在 x86_64、C++17、既有 GCC 14.2 SDK 头及 libc++ 22.1.8 构建头测量。不用开发板，不把 LP64 结果外推到 armv7l ILP32。

新增覆盖：`CATALOG.tsv` 中 585 个固定类型表达式，而非只检查上轮命中的 10 处。包含 I/O、整数、字符串/容器成员、迭代器、时钟、随机引擎、线程、文件系统、bind、智能指针、原子别名、正则等 20 族。每项在 `CATALOG_SOURCE_EVIDENCE.json` 绑定两侧实际源头文件命中、行号、上下文和 SHA。源代码头负责定义发现；实际生效配置由 SDK/构建头探针验证。

这是**有限清单，不是所有标准版本/扩展/任意模板实参的全集**。容器采用明确的 `int` 等实例、默认 allocator/comparator/hash；不同参数可改变嵌套类型。已测同名类型对具体实例成立，不继承到其他实例。清单中的同族头命中仅是选取依据，具体类有没有该成员由实例探测决定；不把同族其他类的同名成员挪用。

模板的嵌套类型数量并无有限的“所有实例”。尚未覆盖 C++20/23/26 专有设施、debug/hardening/替代命名空间配置、用户 allocator/fancy pointer、自定义 char_traits、条件构建分支和用户特化。发现头布局与预期路径不同的记录在 `CATALOG_MISSING_HEADER_PATHS.json`；不把缺路径当作缺接口。

## 类型编码与同一性

使用 `__PRETTY_FUNCTION__` 保存展开显示名，`sizeof/alignof` 保存尺寸，`typeid(TypeToken<T>).name()` 保存编译器给出的类型编码。通过外层模板保留 cv/引用，避免直接 `typeid(T)` 丢掉这些限定。独立正向对照断言 `int=i`、`long=l`、`long long=x`、`const long&=RKl`。同时保存 `readelf -Ws --wide` 中 `abi_identity(TypeToken<T>)` 的实际 ELF 符号。

两库类型编码不同记 `DIVERGENT`；相同记 `IDENTICAL`，严格解释为本配置下该具体类型表达式的编码身份相同。显示名保留：libc++ 的 preferred-name 属性可能把规范类模板显示成别名，不能仅凭这种显示差异认定不同类型。**IDENTICAL 不证明两套库的同名类定义、布局或行为相同。** 此扫描与布局/状态验证正交。

无成员或编译失败记 `NOT_AVAILABLE`，保存所试表达式与实际失败，不替换模板实参。每个成功表达式每侧五轮具体输出一致；测量程序只做类型查询，不调用平台业务接口。

跨包核查仍使用冻结安装头及 3,085 个 x86_64 ELF。标准库自身调用不计为两个平台包之间的新边；公开安装头、公开函数签名、实际异包消费者是不同层次。头命中不等于 SDK 可用，内联/返回值/生成头/动态间接调用等洞继续保留。名字编码差异不能仅靠类型名交集查，要回到函数身份与源码结构链。
