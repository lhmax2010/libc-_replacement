When build_with_libcxx is set, build bpftrace-static from the same
source tree instead of installing the prebuilt Source1002 binary:

- add static BuildRequires (bcc-tools-static, libbpf-static,
  liblzma-static, zlib-devel-static);
- switch the static link to -shared-libgcc so glibc pthread
  cancellation uses a single unwinder; the C++ runtime stays static;
- preserve the original LDFLAGS and configure a separate build-static
  tree with STATIC_LINKING=ON and the static libclang archive, keeping
  the ordinary shared build unchanged;
- install the new static binary when the toolchain is clang, and keep
  the prebuilt Source1002 binary for GCC and undefined-toolchain builds.

Add static-link-libbpf.patch and apply it in prep: the local
LIBCLANG_STATIC_PATH extension linked -lbpf although libbpf.a was
available. Use ${LIBBPF_LIBRARIES} so that the static binary depends
only on glibc and libgcc_s.

Verified: armv7l/aarch64 static DT_NEEDED exactly libm, libgcc_s, libc
and the loader; armv7l board paired tests 12/12 against the prebuilt
binary; shared-libgcc cancellation probes 20/20. GCC and
undefined-toolchain build paths retain their existing behavior.
