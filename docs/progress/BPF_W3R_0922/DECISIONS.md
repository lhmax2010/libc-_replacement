# 自行判断、方法选择与未闭合项

1. 未按IP识别板子。每个板端脚本都先核验uname -r含rpi4、uname -m严格armv7l、os-release的ID为tizen；三项通过才启用获授权的SDB root。未使用PC sudo。
2. 首次非root只读探测不能读取上轮root上传文件；原始Permission denied保留。之后仅使用任务允许的SDB root重查，不修改文件标签或权限。板端readlink不接受多个参数，原退出1保留，改为逐路径循环只读查询。不存在隐瞒初次失败的情况。
3. 板端无cpio/busybox。为执行规定解包流程，将已有ARM构建根的cpio复制到唯一获准工作目录，SHA `b8e9cb4a96dade226d2659381043d279e227c734374914f8325d79d6946301b7`，仅依赖libgcc_s/libc/loader；检查版本后用于rpm2cpio管道。没有安装工具、改系统PATH或复制到/usr。此为在任务目录提供解包工具的实施选择，源文件和实际命令均已申报。
4. 解包前验证RPM内路径只有预期ELF与许可证目录/文件，且extract目录不存在；pipefail保留管道失败。候选直接运行于extract，不建立系统符号链接。TMPDIR/HOME/XDG_CACHE_HOME指工作目录，core被关闭；每项20秒上限，仅作防遗留进程保护，实际均未超时。探针使用原二进制/参数/断言。
5. 内核脚本选候选实际-l中存在的tracepoint:sched:sched_switch，不假设名称；脚本触发即退出。每项按候选→原件顺序，BEGIN/tracepoint/interval各三次，不并行。计时为宿主单调时钟包围远端执行，含传输命令开销，不当作纯程序性能。
6. 取消按既有四模式各5次形成每组20次。实测共享20/20、静态也20/20；不因为历史预期静态崩溃而改结果。ARM结果不可支持“任意架构静态libgcc必崩”，也不否定此前特定x86_64实验。不同架构机制差异未在本轮追加排查。
7. 所有实际测试均通过后按授权清理工作目录，先记录每文件SHA并拉回全部输出，再删除目录内普通文件/空目录，独立核实路径不存在。未删除本地RPM/ELF/探针；可重新部署。结束挂载与开始字节一致，root模式恢复，系统无bpftrace包/路径。
8. 固定源码实际上为上游4.14.1提交，旧诊断报告已注明该边界。板端rpm --version也为4.14.1；不把它称为已证明的部署4.14.1.1源码。真实ro观测与固定源码条件吻合已确认；没有插桩读取DSI，也没有重跑rpm --test。MSM内部错误处理不另作未经取证的根因判断。
9. 两轮构建核对原意只读，但提取.text的llvm-objcopy没有独立输出ELF，实际改写四份已有tmp主包解包副本，**违反只读纪律**。原命令与脚本保留，不恢复或改写现场；详见INCIDENT.md。随后内存只读解析原RPM复核了表中原始ELF/.text数据。当前--version加execve trace没有编译；其结论不替代历史逐目标进程证据。ccache命中数、历史同期竞争负载、ARM提速唯一原因均NOT_OBSERVED。
10. ARM主包ELF及.text不同，aarch64均相同。只登记，不擅自归因或修改；这是W4应审阅的新挂账。aarch64旧轮时长13.37min而非两小时，按原始事件时间纠正叙述，不修改旧记录。
11. rpm安装验证留待镜像阶段。当前能交W4审阅的是限定用例的可写区执行等价及取消数据，不是RPM安装/%post或全功能、全平台等价证明。仍不推sandbox/包仓、不起QuickBuild。
