libcxx: preserve forced unwind across header catch-all sites

Add a __forced_unwind handler before the catch-all handlers in the
consumer-instantiated istream, future, and string paths. The handler
preserves each path's existing state update where applicable and
rethrows so POSIX cancellation can continue unwinding.

This follows the corresponding libstdc++ guard shape. It depends on a
libc++abi that exposes the GNU-compatible __forced_unwind type and
correctly resumes foreign forced unwinds.

Validated on x86_64 and ARMv7l for blocking getline and packaged_task
cancellation, plus selected upstream iostream, future, and string tests.
Not covered: AArch64, LTO, concurrent cancellation stress, or mixed
runtime frame traversal beyond the validation cases.

中文说明：在消费者实例化的 istream、future 与 string 头文件路径中，
于 catch-all 前加入 forced-unwind 重抛防护；保持原有状态设置语义，
并依赖 libc++abi 提供兼容类型与正确的外来强制展开重抛支持。
