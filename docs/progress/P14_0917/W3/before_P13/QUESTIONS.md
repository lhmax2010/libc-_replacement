# 疑问与边界

1. W2(d) 已异步提出：如果第二个异常在第一个异常展开期间逸出析构，C++ 会 terminate；外层 catch 无法改变该规则。将分别实测析构内自行捕获、正常退出时析构抛出、展开时析构第二异常逸出，不能替换概念。待人工确认要求的具体语义。
2. P12 的 GNU-only 对照调用的是 adaptor 后端 POD 函数，不是原始 ewk_parse_cookie 的分配失败约定。W3 已完成真实原始入口对照，观察到 bad_alloc 可逸出原接口；不得把 POD 的负 errno 称为原 API 返回约定。
3. 当前反向链的后端是 GNU TU，不是 libc++ TU；生产方向缺真实 libc++ EWK。P13 固定两侧 runtime 版本引用，但不把反向实测外推为生产方向已验。
4. 新增构建条件：GNU gold 实测可链接。原平台 linker 的失败记录保留；产品 linker/GN/RPM 尚需验证。未改全局 linker、平台配置或运行库。
5. 同步 catch-all 合同不包括线程取消、强制展开、栈溢出、信号故障、析构双异常及其他 terminate 路径。本轮按任务书不测试取消，不据此声明取消安全。

6. W3 新增阻断：真实 provider 分配失败时返回后存在稳定累计的未配对分配；原始 GNU 入口也有。FDE/CIE 证实 ewk_parse_cookie 没有 personality/LSDA。完整释放保证尚未成立，是否另行授权处理 provider 异常清理支持已异步提问；未改平台源码/配置，未用测试计数器强行释放未知所有权指针。
7. “与原接口一致、不能更差”需分开：bool 类型和正常样本对齐，但原始 GNU 接口可向应用抛 bad_alloc，adaptor 将其转 false/ENOMEM。该转换按本任务明确要求实施；不能说异常传播完全不变，也不能仅凭样本给出任意错误下不更差的承诺。
