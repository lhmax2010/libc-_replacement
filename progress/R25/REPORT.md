# R25：迁移切面的 ABI 边分析与两笔账目核查

## 结论摘要

本轮只复用 R22/R24 的 **483 个源码 RPM 身份、1,234 条真 C++ ABI 边**和 R23/R11 的既有表，没有重扫平台仓、构建、安装或修改既有文档。

1. 六个切面上“未迁消费者 → 已迁 provider”的边依次为 **0、953、574、259、118、12**；涉及消费者依次为 0、360、137、52、20、4 个源码 RPM，provider 为 0、9、52、50、32、6 个。反向“已迁消费者 → 未迁 provider”在六个切面均为 **0/1,234**。
2. 共有 **1,191/1,234 条去重边**至少跨过一个切面，涉及 **75/483 个去重 provider 源码身份**。其中 1,137 条观测到 `std::`、异常或 vtable/RTTI 等客观标记，54 条需人工判读；现有证据能证明“不跨运行时语义”的边为 **0/1,191**。
3. 严格“任一时刻零跨界边”下，无向图形成 **99 个不可再拆原子单元/483 个源码身份**：97 个单节点、1 个 13 包单元、1 个 373 包单元。最大单元跨阶段一、阶段二三层、阶段三和厂商单列集合；第二个 13 包单元跨阶段二第 0/1 层。
4. gtest/gmock BuildRequires 消费者为 **153/1,450 个源码包实例**：阶段一 4、阶段二 121、阶段三 10、厂商单列 1、483 集合外 17，合计 153。已知的“阶段二 121 + 阶段三 10”之外 22 个，精确去向为 **4 + 1 + 17**。
5. `13 + 450 + 16 = 479` 是三阶段源码 RPM 身份；厂商“5”是二进制包 Name。`pen-wave` 与 `pen-wave-devel` 共用 `pen-wave-1.4.0-2.src.rpm`，所以厂商侧是 4 个源码身份，正确闭合为 **479 + 4 = 483**，不是阶段表与厂商源码身份重叠。

## 六、483 差 1 的真实原因

`migration_packages_483.tsv` 的单位从头到尾都是源码 RPM 身份：阶段一 13 + 阶段二 450 + 阶段三 16 + 厂商单列源码身份 4 = 483。背景中的厂商 5 指二进制包 Name：

- drm-service-core-tizen → drm-service-core-tizen-0.3.9-0.src.rpm；
- hal-api-drm-haltests → hal-api-drm-1.0.5-1.src.rpm；
- hal-backend-drm-generic → hal-backend-drm-generic-1.0.3-0.src.rpm；
- pen-wave、pen-wave-devel → 同一个 pen-wave-1.4.0-2.src.rpm。

所以差 1 来自 **5 个二进制 Name 映射为 4 个源码身份**，不是同一源码身份同时出现在三阶段表和厂商集合。`vendor_five_to_four_accounting.tsv` 验证四个源码身份在 483 表内均恰以 `VENDOR_PREBUILT_SEPARATE` 出现一次。
